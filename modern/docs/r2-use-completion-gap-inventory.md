# R2 原版商品 USE／製作功能缺口清冊（平行支線）

> 來源：凍結 `custom/inc-item-data.cgi` 逐一 `@@ITEM`／`@@USE`，2026-11-23 檢查本分支 `work/r2-use-completion`。本清冊是**來源宣告對現行執行 Registry** 的缺口，而不是聲稱某 USE 已完成或 Oracle 全覆蓋。只修改 `modern/`。R4 EVENT／SortDT／36h 僅介面待整合，未複製 R4 引擎。

## 確認總數與缺口層級

- 原版 ITEM **79** 筆，USE **116** 筆；現行正式 `getRule` 僅 `79/0` 與 `14/0` 兩筆，其他 **114** 筆仍未接入正式玩家命令。
- 靜態宣告特徵可重疊：無明示回呼／職業／EVENT／其他需要條件 **15** 筆；有回呼或 inline local func **56** 筆；職業條件／修正 **42** 筆；直接提到 EVENT 條件或 DTevent **1** 筆；公會 **0** 筆；其他熟練／人氣／分數門檻 **49** 筆。
- **已完成演算法／來源驗證 ≠ 玩家功能已接入。** 79/0 是現有受控玩家操作。14/0 雖有此支線程式和 Oracle，必須在實際 CI 與重啟整合成功後才可判定完成。剩餘 114 筆目前均由 Registry 拒絕，不可標為「原版不支援」。
- 分類中的「否」只代表這份 USE 宣告未直接引用 EVENT，**不證明回呼內部不會讀 EVENT**；未審閱的 callback 均維持嚴格拒絕。

## R4 整合介面與實作限制

現在 `use-item` 對未知 `world.events`、非空／未知 `period.eventState` 仍 fail-closed；不應將它們設為空物件來放行。未來如 source USE 需要 `needevent`，應由 R4 審閱的 EVENT 投影提供可核對、可重播的事件生效資訊，包含事件鍵與生效時序，R2 只做來源判斷。跨越 36 小時的時間推進與 SortDT 仍由 R4 統一處理。

無回呼、無 EVENT 的正常製作優先以同一 `use-item` Registry 載入，不另設每件商品專用 command。接入前仍必須先對該組合法材料／GET 機率／原版職業縮時與 overflow／CheckWholeStore 以凍結 Perl 做直接差分，並通過 HTTP、CAS、雙世代存檔和重啟的玩家流程。未通過時狀態維持未接入。
