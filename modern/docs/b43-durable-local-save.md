## 玩家可以怎麼用

1. 更新現有工作分支，進入 `modern`，執行 `npm run dev:local`；開啟 `http://127.0.0.1:4173`。
2. 在原版風格繁中「自店／交易／倉庫」完成原版開店、真市場進貨 #10、合法上架、自然販售／二次再進貨。
3. 按「**儲存世界**」：後端驗證目前世界的 `revision` 及磁碟存檔世代，再將整個來源世界狀態落盤，保留 world ID、行動時間、日期、資金、庫存、原版79格市場／原始 CSV、人氣、各類日帳與持有費小數。
4. 停止本機 Node 程式，完全重新執行 `npm run dev:local`。畫面會顯示已有幾代存檔；此時按「**載入存檔**」，世界版本與真實帳務、商品都應和按下儲存時完全一致。接著能繼續在同一世界真進貨或自然販售，再次儲存。
5. 「儲存」**不是即時自動存檔**：最後一次儲存後若再交易卻未按儲存就關閉 Node，新變更會遺失。已存在存檔時，不允許直接初始化一個新世界覆寫它；已載入／正在營業的世界也不可被舊存檔悄悄覆蓋。

存檔根目錄預設為 `modern/.local-data/`，已加入 `.gitignore`；也可在啟動服務前自行指定環境變數 `AKIMONO_SAVE_DIR`（必須是本機服務程式有權限讀寫的資料夾）。本機 HTTP 服務依然只綁定 `127.0.0.1`，沒有公共登入或多使用者存檔服務。

## 實際耐久性與安全邊界

- [儲存模組](../src/local-world-save-store.mjs) 使用兩個固定檔名 `world-a.json`／`world-b.json`，單調遞增的 `generation`、格式版本 `akimono.local-world-save.v1`，保存完整經過 `validateMemoryWorld` 與受控 Standard Street 真來源市場校驗的 JSON 世界。
- 每個世代的內容由 SHA-256 校驗（**用於偵測損毀，不是對抗惡意竄改的簽章**）；資料先寫到同目錄獨立暫存檔、`fsync` 檔案，再用同目錄原子 `rename` 對應世代槽，支援平台另同步目錄。Windows 不提供此模組的目錄 `fsync` 保證，不能宣稱所有 OS 對斷電具有相同保證；整個設計**不支援多個 Node 服務同時寫同一個存檔資料夾**。
- 讀取時校驗 JSON 格式、來源世界語義、版號、世代奇偶槽、雜湊與完整資料重編碼；最新存檔損毀時可使用**上一個仍有效的完整世代**，回報發生備援回復；兩份都損毀則拒絕載入與覆寫，避免自行建立「修好的」假世界。
- 存檔世代與遊戲 `revision` 分別檢查，過期的前端請求或不同 world ID 不能偷覆寫。不自動進行原版期末結算，也不新增未知商品庫存、街道事件或缺失世界欄位。
- [Node／HTTP 重啟驗收](../tests/b43-durable-world-save.test.mjs) 包含兩代保存、真買入及自然販售後存檔、**真正殺掉 Node 進程再起服務**、載入後第二輪續售、來源 WorldState CAS、不合法存檔拒絕、損毀最新世代後備援回復及重新存檔。

## 還沒完成的真正營業閉環

目前還不能跨期。原版 `inc-turn.cgi` 是先執行自然銷售、必要 FUNCTURN／FUNCSALE、`SortDT`，再於期界呼叫整段 `inc-period.cgi`，其副作用不只是收支歸檔，還有領地人口／事件／稅務／公會／榜單／備份。現有世界缺少部分原版領地事件資料，不能從空值猜出期末數值。下一步必須建立來源可審核的真世界狀態與期末轉場，原版 Perl／Node／HTTP 在同一世界實測完整跨期，才開放 UI 跨越36小時邊界。其他商品、其他街道、登入與多人仍未支持。
