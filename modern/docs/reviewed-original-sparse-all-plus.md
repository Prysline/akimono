# B-37｜全部 79 項標準街商品原始 PLUS 編譯與原版稀疏供貨對照

> **本階段是完整商品 PLUS 子步驟，不是完整遊戲週期。** 固定原版 Core 的 `inc-turn.cgi` 原文市場供貨迴圈、`whole.cgi::CheckWholeStore`，與全部標準街商品的 `PLUS` 宣告，均在受控記憶體測資中直接執行 Perl 並逐欄比對 Node。此前的自然銷售／回呼／人口變動／時間切段／結算／事件／世界檔 I/O **都沒有執行**。

## 原版來源、完整清點與重要訂正

- 固定 Core `inc-turn.cgi` Git Blob：`b8a4980275f475a952846a8d6072fad45f8dff50`；`plug/whole.cgi`：`778badaf157326bcfd1f8fa1e310d94f94995eb3`；`inc-makeitem.cgi`：`1da8cce1e76ad6159325a37faec68efaa82c7f69`。以上皆為**19份原封不動 Core 快照**的一部分。
- 真正 `custom/inc-item-data.cgi` 的 79 項 ITEM 中，<b>59項有明文 `PLUS`，20項沒有</b>，缺項 ID 為 **18、19、24、26、27、28、29、35、36、38、67、70、71、72、73、74、75、76、77、79**。原版編譯器 `ClearBuffer('item')` 預設 `plus=0`，明文 `PLUS` 透過原版 `GetTime` 轉為秒；Node 僅接受與原始 DSL **79格逐項完全一致的固定文字清單**。
- **修正上一輪最初掃描錯誤：** #16「皮革加工入門」及 #17「木工加工入門」皆明文 `PLUS 20h`，不得漏列。B-37 用專案真正的 DSL 解析與原始 Perl 直接編譯交叉驗證，正確合計59項，而不是先前快速掃描的57項。
- 實例：#1 藥草 `-20m` → -1200秒；#10 書本寫作工具 `+20m` → +1200秒；#16/#17 各 `20h` → 72000秒；#40 木刀 `-1h` → -3600秒；#62 廣告包 `5d` → 432000秒；#79 禮物卷未宣告 PLUS → 0秒。
- **有明文 PLUS 不等於必然產生正庫存**：原版先隨機算出數量、按正負供貨操作，再執行**一次**全79商品的上限／下限檢查。`+=` 即使數量0也可能將 Perl 未定義槽位變成已定義；Node 分開保留79格數值投影、`originalWholesaleCsv` 與 `sparseWrittenSlots`。
