# B-54｜本機真營業指令：磁碟復原後，相同世界版本的來源亂數不可重抽

> 2026-11-21。此工作是 B-43 真磁碟存檔和 B-41 真 #10 自然販售的**正式本機 HTTP 執行層改進**。它是有意識的本機遷移政策，**不是**聲稱重現原版 Perl 跨程序的 `rand()` 種子或事件生命週期，也不代表原版 36 小時跨期結算已完成。

## 問題

在 B-41～B-53 期間，本機服務對原版 59 PLUS 子步驟及真自然販售的 `randomDraws` 使用 `crypto.randomInt(1000000)`。來源 Perl／Node 公式能用共同抽樣逐項比對，但**玩家真本機服務**每次呼叫會拿到新的樣本。若上一版本已儲存、下一個時間片未存就關閉 Node，玩家重新讀取舊版本、再次執行相同時間片便會得到**另一個市場／銷售結果**。這也使未來把 EVENT 真回呼接入之後的「重試直到抽到有利事件」問題更嚴重。

## 實際修正

[本機來源指令亂數政策](../src/local-source-command-draws.mjs) 使用 Node 內建 SHA-256，以**來源世界 worldId、revision、nowSeconds、指令類別及全部經驗證參數**作為命令範圍，不接受前端送入的亂數。對固定樣本序號與重抽 nonce 做摘要，以無偏的48-bit rejection sampling 映射為原 B-37/B-41 接受的百萬分位整數；最多產生原版59 PLUS 的118筆或自然販售＋PLUS 的121筆。該演算法沒有記憶體隱藏計數器：同一 WorldState revision、同一時鐘、同一指令及相同參數**不管在同一 Node 還是關機／重啟後**都得到**相同的抽樣串流**，甚至對完整120筆亂數先行探查後只提交實際消耗前綴也不會改變資料。若不同 revision／不同指令／不同參數則導出不同串流，成功 CAS 只會一次推進世界版本。

[本機 HTTP 介面](../scripts/dev-local.mjs) 現在正式用此政策替代不可復原的 `randomInt` 作為來源供貨及販售的抽樣。**來源演算法仍是 B-37/B-41 同一套原版對照的算式**；只有原先呼叫時當場生成的隨機輸入，換成可以由世界快照重播的來源操作輸入。原版 Perl 的 process-random `rand()` 並沒有跨重啟可重演的保證，因此這項政策是為本機存檔可恢復性設計的**明確遷移差異**，不是原版 RNG 完全等價。

此方法不防止知道 worldId/revision 的人預先推算結果，**不是秘密種子或公開多人遊戲的防作弊方案**。此本機介面只綁定 `127.0.0.1`，仍無多人或鑑權。內建 `AKIMONO_E2E_DETERMINISTIC_RNG=1` 歷史 CI 測資分支保留，不影響真本機指令預設政策。

## 真 HTTP 及磁碟重啟驗證

[原 B-43 真存檔 E2E 增加 B-54 測試](../tests/b43-durable-world-save.test.mjs)：

1. **不用舊 E2E 固定0樣本**的真本機 Node 服務，建立 v2 玩家世界、開店、執行實際原版59 PLUS（3600秒）讓市場有 #10。
2. 真市場買 #10 → 真展示架上架 → 儲存該商店／市場／城市／時間／revision。
3. 進行30分鐘來源自然販售與 PLUS，讀取**全部**更新的商店、市場、城市、事件未知標記、時鐘。
4. 不保存該次快轉，**真的 SIGTERM 關閉 Node**，再啟動第二個 Node、載入 B-43 原快照；故意送一個過期 `expectedRevision` 確認拒絕且不消耗來源世界版本。
5. 對同一個 `expectedRevision` 再快轉30分鐘，逐欄比對兩次 HTTP 的完整 WorldState，必須完全相同（包括銷售量／金錢／PLUS 供貨／時鐘／城市、`period.eventState=null`）。
6. 將重播後的結果寫入 B-43 磁碟，關閉第二個 Node，再開第三個 Node，載入後仍必須逐欄完全相同。即使前端送 `randomDraws` 雜訊，服務也不接受前端指定亂數。

[獨立政策測試](../tests/b54-repeatable-source-command-draws.test.mjs) 驗證世界／revision／時鐘／指令／參數所形成的樣本隔離，和樣本數、分布範圍、非法來源輸入拒絕。

## 未完成與下一步

**不可宣稱這代表原版事件已經移植：** B-52 時間推進後會標記 `period.eventState=null`（原版 EVENT 動態回呼未實作），B-53 的17個可編入 EVENT 只是定義 metadata，**沒有**真 EVENT 起訖、群組、回呼、資金／人氣／市場／城市副作用與 Perl hash 亂數順序。B-50 真期末兩期目前仍是不可提交的原版整合前綴；尚未在玩家 v2 世界做真跨36小時原子 CAS、磁碟存檔重啟、次期續售。

下一步不應把重播機制當作完整事件系統；必須在真正 source-reviewed EVENT 引擎中維持**單次結算或同版重試同一結果**，再把商品 FUNCTURN/FUNCSALE、原版全期末／領地及必要的磁碟副作用按順序整合。只有用同一繁中介面做到「開店→真進貨→合法上架→自然售出→原版36h真跨期→B-43落盤→重啟→下一期繼續營業」才能請使用者一次人工驗收。
