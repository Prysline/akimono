# B-36｜原版多商品 PLUS 同時間片順序與稀疏批發

**這是來源已審閱的局部週期，不是完整市場週期。**

## 固定來源與條件

- 不修改固定原版 Core `inc-turn.cgi`（Git Blob `b8a4980275f475a952846a8d6072fad45f8dff50`）與 `whole.cgi`（Blob `778badaf157326bcfd1f8fa1e310d94f94995eb3`）。
- 真正標準街 DSL 經原版 `inc-makeitem.cgi::GetTime` 可核對：商品 #1 藥草 `PLUS -20m` = -1200 秒、批發上限1000；商品 #10 `book-make` `PLUS 20m` = +1200 秒、批發上限10；商品 #40 木刀 `PLUS -1h` = -3600 秒、批發上限600。
- **僅以上三個商品的 PLUS 啟用。**固定來源 Perl 原文迴圈按 ID 1→10→40 跑，其他76項在測試層人工設為0；完成迴圈後，執行一次真正原版 `CheckWholeStore`，檢查全部79項上限。
- 來源初始人口 `DTpeople=500000`、原版設定 `MAX_USER=50`；世界只有一間真標準街新店，初始 #63 展示架工具1個、#79 禮物卷5張。測試時間片代表「前段自然銷售與回呼已結束」後的受控輸入，**不執行實際自然銷售、人口變化、時鐘流動、事件或決算**。
- 亂數由外部給定0～999999整數，表示原版 `rand` 單位輸入的百萬分之一；在 `0<add<1` 時，來源會再消耗一次抽樣。這不表示 Perl 與 Node 的偽亂數種子或序列相同。

| 600秒；[0,0,0] | 5 | 0 | 10（受上限約束） | 0 | 0、9、39、78 |

負向供貨使原本未定義的批發索引0與39在原版 Perl 中發生賦值、之後 `CheckWholeStore` 將負數裁成0；索引78因新店持有5張禮物卷、批發上限0而明寫0。其餘空欄保持稀疏，不能改成79格字面0。

為了進一步確認真正「扣貨」，另提供**人工起始庫存**（商品 #1=20、#40=10）之直接來源 Perl fixture：相同60秒、抽樣0後變成19、9。此案例只驗證數學符號和原版順序，**不代表原版空白市場實際生成該庫存**。
