# B-55｜真正的原版偷竊／強盜回呼：Perl 執行、Node 逐項對照、GameCore CAS 與磁碟恢復

> 2026-11-22。此里程碑讓**原版兩個 `startfunc` 的副作用確實可修改真玩家商店的 WorldState**。這是一個只給內部開發與來源驗證使用的 callback fixture，**不代表已經按原版 EVENT 機率、hash 迭代順序與完整時間片自然觸發**；繁中玩家 HTTP 尚未開放這兩個事件的真自然觸發，36 小時跨期仍保持拒絕。

## 本輪來源行為

[原版 ITEM DSL](../../custom/inc-item-data.cgi) 中：

- `manbiki`（偷竊），編譯機率 `start 100%` → 1000，`startfunc _local_(400,200)`。回呼在每間商店先以 `rand(1000)>400` 決定是否略過該店；若持有 #64 看門機器人，再以 `rand(1000)>200` 判斷機器人成功防禦或遭到破壞；沒有機器人時對每個有商品的展示架扣除 `int(持有量/10)`，但**不計入銷售收入**。
- `goutou`（強盜），編譯機率 `start 20%` → 200，`startfunc _local_(700)`。用 `rand(1000)>700` 判斷該店是否被鎖定；若有 #64 機器人則直接損失機器人並結束，不額外降人氣／偷商品。否則人氣減 `int(rank/5)`，各展示架商品減 `int(持有量/4)`，同樣**不計入自然販售**。
- 原版這兩個回呼都可能回傳 `(0,事件訊息)`。原版 `inc-turn.cgi` 的 startfunc 返回值 0 表示不把事件認定為已啟動；又因它們的 `basetime=0`、`plustime=0`，**不會留下有期限的 `DTevent` 活動記錄**。不能因為偷竊對庫存產生效果，就創造一筆假的「活動中事件」或當成一筆銷售。
- 本機真商店目前只有來源 #10 書本寫作工具、原版 #63 置物架工具和 #79 禮物卷（#64 看門機器人仍未在真買賣路徑提供）。機器人兩種分支只在原版回呼測資與 Node 原始來源模型對照，**未假造機器人供貨給玩家**。

## 實作

[來源審閱與真回呼效果](../src/original-instant-event-callbacks.mjs) 由 B-53 的編譯清單核對 `manbiki=1000`、`goutou=200`、原版回呼參數、同一來源 `@@ITEMNO"看門機器人"` 對應 #64、原始負責扣商品／降人氣的語句順序與回傳方式。只允許來源單店、79項庫存、原版 #10 展示架、最多2個在原版 `rand(1000)` 可用的百萬分位抽樣；有缺少、額外或非法樣本、源碼漂移、未知商品／回呼，一律拒絕且不寫入世界。

[原版 Perl 真執行探針](../tests/original-perl/original-b55-instant-event-callback-probe.pl) **直接從固定原版 `@@EVENT` 擷取兩段完整的 `startfunc` Perl 程式內容，僅展開原版已確認的 #64 機器人商品編號巨集，透過 Perl `eval` 真執行**，覆蓋偷竊未被選中、12件扣1、9件扣0、機器人防禦／遭毀、強盜12件扣3、人氣5000降為4000、1件貨物卻仍降人氣、機器人擋強盜及空展示架。測試用 `GetMoneyString` 只返回整數字串而不使用原版 GUI 金錢格式，因此訊息字面比對是此**受控格式化測資**，不是原版完整 UI 格式等價。隨機值本身和後續商店資料都由真原版回呼計算，不是人工設定結果。[Perl 斷言](../tests/original-perl/original-b55-instant-event-callback.t)、[Node 對照](../tests/b55-source-event-callbacks-live-cas.test.mjs) 均核對來源完整79庫存槽、rank、現金、訊息、返回值、精確亂數消耗以及不修改輸入。

[真 Standard Street Module](../src/standard-street-module.mjs) 現在有**僅供開發驗證的內部指令** `reviewed-instant-event-callback-fixture`，只在已有合法 v2 世界、已有單店且 `period.eventState=null`（尚不知其他事件）時接受真來源回呼。其結果可走真 `executeMemoryCommand` → WorldState revision CAS，保留所有其他城市、供貨、收入、事件未知狀態；不會稱此指令是自然 EVENT 啟動。沒有對應的本機 HTTP endpoint／玩家介面按鈕。

[B-55 同一世界整合測試](../tests/b55-source-event-callbacks-live-cas.test.mjs) 不是只有造一間假店測函式：測試先在**真正來源 v2 世界**以原始開店、59項 PLUS、買市場商品#10、合法展示架、真自然販售，然後再次從來源市場買#10，**讓原版強盜回呼透過 GameCore CAS 對此真商店降人氣**；測試讀回 `period.eventState=null` 不會被當成已完成 EVENT 引擎。之後將受影響的**完整商店／市場／城市**真的存入 B-43 雙世代磁碟，再讀回同世界快照，並繼續走 B-41 真自然販售以確認後續經營不會被回呼破壞。失敗或過多亂數樣本的命令要證明世界 revision 完全不變。

## 仍缺少的核心玩家功能

**本次不是原版17事件的完整實際執行。** 原版 `inc-turn.cgi` 一個時間片先自然販售、物品回呼、排行、可能的期末和市場 PLUS，之後才使用 Perl `keys(%EVENT)` 順序處理事件到期、啟動及立即回呼。B-55 只讓兩種立即回呼的**效果**可透過內部限定命令接到世界，尚未由真完整事件啟動器選擇它們、也沒有原版所有其他15事件與回呼的效果及隨機序列；不能自行在玩家時間片只抽這兩項就宣稱忠於原版。真正玩家端 **仍沿用 B-41 的時間片，將 `eventState` 誠實標成未知**。也尚未完成 B-50 真期末的完整玩家 CAS、事件／商品其他回呼、原版資料 I/O 的可恢復替代，36h原版期界仍拒絕。

下一步繼續讓**已來源驗證的回呼接入完整事件 gate/時間片的單一原子 CAS**，逐步完成其他 EVENT（例如資金援助、人氣提升、抽獎、商會戰等）及必要原版亂數／來源存檔事件語義；再實際驗證在同一繁中介面「開店→原版進貨→上架→自然販售→36h真正跨期結算→存盤停止Node→重啟下一期再買再賣」，到整個閉環可操作才由使用者**一次集中人工驗收**。
