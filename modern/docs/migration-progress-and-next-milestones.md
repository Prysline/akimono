## 下一個優先目標：轉向最小可玩閉環

以 B-30 級別的來源回歸測試守住不變規則，不再單純用測試數量當作主要交付。

### 31｜設計可測試且隔離的正式介面（對應任務04）

明確輸入／輸出與可插拔介面：`Game Core`（決定可否操作及狀態變化）、`Street Module`（標準街商品、回呼、設定）、`World State`（商店、市場與時間，單機／多人儲存實作分離）。使用**受控的合成記憶體**作第一個 `WorldState` adapter，保留所有已證實的數值、欄位、異常順序與來源歸屬；不把尚未審閱的回呼假裝成功。

**可驗收**：固定商店快照 → 交易命令 → 唯一的狀態變更結果，包含合法、失敗、不支援與不應修改來源的情況；既有 B01～B30 回歸仍成功。

### 32｜串第一條標準街可重現經營循環（對應任務05～07的前置整合）

合成新店 → 商品進出 → 使用與陳列 → 批發／市場或銷售 → 時間／週期結算 → 產生可儲存的狀態快照。各節點由已核對的原版子模型組合；尚未支援的實際事件、回呼、跨店結算與隨機結果**明確標示不可用或以來源可驗證的測資固定**，不是偷偷跳過。

**可驗收**：每步前後快照、金錢、庫存、時間、經驗、供需與來源預期比對一致；失敗情境不意外改變狀態。

### 33 起｜可靠存讀檔、繁體中文網頁、跨街道實測，再開放多人

在純核心閉環驗收後，才選擇和接入單機儲存 adapter（含鎖／備份／提交失敗測試），建立網頁操作介面；再跑麵店兩個特殊規則，補全標準街必要玩法。**多人主帳號與世界權限**必須在單機核心操作、儲存及授權契約可驗證後才實作。

**安全與版權界線**：原本素材授權尚須單獨確認，發佈前不能將未知授權的圖片／音樂一起公開；原版程式的歷史異常只列錄，不擅自改其計算順序。

> 專案狀態：規則驗證已形成可執行測試基礎；正式最小 Core、單機可玩版與多人世界**尚未達驗收**。不要把 B-30 或 Node/Perl CI 的 100% 綠燈當成整款遊戲完成。
